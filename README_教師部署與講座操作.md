# AITE 情緒色彩實驗室 × Chatbot 心得分享 × 全班色彩牆

**講座**：《AITE 教學與課程融入師培課程》｜2026 年 11 月 19 日｜國立臺北藝術大學  
**講座／活動設計**：國家教育研究院課程及教學研究中心 黃彥融副研究員

## 這套網頁做什麼？

同一個網址包含：

1. **情緒色彩實驗室**：六種色彩互動、畫面變化、藝術觀察與反思問題。
2. **AITE Chatbot 心得分享**：學生勾選體驗的 Chatbot，填寫感受與對師資培育／藝術教育的想法；作品名稱、作品網址選填。
3. **全班 AI 體驗情緒色彩牆**：學生選一種色彩代表 AI 體驗，願意公開的心得以彩色卡片呈現，能依色彩篩選。
4. **教師自己的 Google Sheet**：所有提交都在 Sheet；「只提供講師閱讀」的心得不會顯示在公開牆。教師可將任何公開心得改成「隱藏」。

**學生不需要 GitHub 帳號，也不需要操作 Google Sheet；** GitHub 只用來放教師的網站。學生有興趣時才另外生成作品、填作品網址。

## 你會拿到哪些檔案？

| 位置 | 檔案 | 用途 |
|---|---|---|

## 第 1 步：建立 Google Sheet 與 Apps Script（先做這個）

1. 開啟 <https://sheets.new>，新增一份**你的** Google Sheet，建議命名為 **「2026-11-19 AITE 體驗回饋」**。
2. 在試算表點 **「擴充功能 → Apps Script」**；這樣 Apps Script 會自動綁定到這份 Sheet。
3. 打開原有的 `程式碼.gs`（或 `Code.gs`），**刪除預設內容**，完整貼上套件 `google-apps-script/Code.gs` 的程式碼並儲存。
4. 編輯器上方函式選單選擇 `setup`，按 **執行**，依畫面完成 Google 授權。
5. 回到 Google Sheet，應該看到兩張新工作表：**「心得分享」**及**「活動統計」**。`setup()` 會記住這份 Sheet 的**純 ID**，不必手動貼上整串 `/edit?gid=0` 網址。
6. 到 Apps Script 右上方 **「部署 → 新增部署作業」**，類型選 **「網頁應用程式」**：
   - **執行身分**：選 **我**（擁有該 Google Sheet 的帳號）。
   - **誰可以存取**：選 **所有人**（如果學校／機關帳號的管理政策允許）。
   - 按 **部署**，複製網址。請確認網址是 `https://script.google.com/macros/s/.../exec`，**不要**用 `/dev` 測試網址，也不要用 Google Sheet 網址。
7. 可以用瀏覽器測試該 `/exec` 網址。若出現 `{"ok":true,...}` 類型文字，代表服務已啟用；如果顯示登入頁或存取拒絕，請檢查部署權限。

> **重要**：不要將 Google Sheet 設為「知道連結的任何人都可編輯」。學生只會經由 Apps Script 投稿。某些機構 Google Workspace 可能禁止公開網頁應用程式；若無法設定「所有人」，須使用允許部署的帳號或詢問管理員，**不能以分享試算表編輯權限取代**。

## 第 2 步：把 Apps Script 網址填到 GitHub 網頁

1. 用一般文字編輯器開啟 `github-pages/index.html`。
2. 搜尋 **`GAS_WEB_APP_URL`**，找到以下這一行：

   ```javascript
   const GAS_WEB_APP_URL = '請把GoogleAppsScript部署後的exec網址貼在這裡';
   ```

3. 只把**兩個單引號中間**改成第 1 步拿到的 `/exec` 網址。例如：

   ```javascript
   const GAS_WEB_APP_URL = 'https://script.google.com/macros/s/你的部署ID/exec';
   ```

4. 儲存 `index.html`。**不要把 Google Sheet 的網址、API Key 或個人帳號密碼貼進 HTML。** Apps Script 的公開部署網址本來就是公開端點，請勿在 Sheet 存放敏感資料。

## 第 3 步：將網站放到 GitHub Pages

1. 登入你的 GitHub 帳號，開啟 <https://github.com/new>，新增一個**公開**儲存庫。例如：`aite-color-lab-2026`。
2. 在儲存庫上傳**修改好網址的** `index.html`（只需要 `index.html`，無須上傳 `Code.gs`、README 或整個 ZIP）。請確認它位於儲存庫的**根目錄**。
3. 開啟 GitHub 儲存庫的 **Settings → Pages → Build and deployment**。
4. `Source` 選擇 **Deploy from a branch**，分支選 `main`，資料夾選 `/(root)`，按 `Save`。
5. 等待 Pages 發布完成（可能需要幾分鐘），再開啟 GitHub 提供的公開網站網址。通常形如：

   `https://你的帳號.github.io/aite-color-lab-2026/`

6. 用**手機**與**無痕視窗**測試一次：色彩可切換、AITE 按鈕可開啟、心得可以送出、Google Sheet 有新列、公開心得牆看得到回覆。
7. **最後**才把 GitHub Pages 網址轉成 QR Code，放到你的簡報中。

GitHub 官方說明：<https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site>

> GitHub Pages 是網站展示位置，**不是** Google Sheet 的資料庫。只有教師要操作 GitHub。不要把試算表或收件後端的程式碼傳給學生。

## 第 4 步：當天講座 30 分鐘建議活動

| 時間 | 活動 | 師培生要做什麼 |
|---|---|---|
| 0–5 分 | **體驗色彩實驗室** | 選顏色、看場景改變、思考色彩與情緒的不同解釋 |

**作品不是必做。** 若有學生生成教案、圖片、音樂、互動網頁或其他教學成果，可以填入一個公開 `https://` 網址；若沒有作品，就留下使用心得。

## 收件與公開規則

- 學生只須填寫**暱稱／組別**，不需要學號、電子郵件或真實姓名。
- 表單包含：體驗 Chatbot（複選）、代表色、使用感受、教育想法、期待建議、選填作品連結，以及公開意願。
- 若選「同意在全班色彩牆展示」，Sheet 的 **L 欄**為「同意公開」，**M 欄**為「公開」，會顯示在網站上。
- 若選「只提供講師閱讀」，Sheet 的 **L 欄**為「只給教師」，**M 欄**為「隱藏」，不顯示在公開牆。
- **撤下某則公開回覆**：到 Google Sheet 的「心得分享」工作表，將該列的 **M 欄「展示狀態」由「公開」改為「隱藏」**。刷新網站後就不再顯示。
- 任何人只要有公開 GitHub 網址就可能看到已公開的回覆，**不是僅限同班學生觀看**；請在課堂上說明，並提醒學生避免貼上個資、學校機密、未經授權的音樂／圖像或私人對話紀錄。
- 此版本沒有使用者登入或審核佇列，適合短期講座和非敏感回饋；公開部署可能面臨外部亂填。若活動規模變大，應改採身分驗證、審核或其他受限存取機制。

## 先做一次「測試投稿」

1. 在網站選「色彩體驗」，點選其他顏色，確認畫面及提問改變。
2. 進「心得分享」，用測試暱稱、體驗工具、感受和教育想法填寫，選**公開**後送出。
3. 等畫面顯示「**已確認收件**」。程式會先投稿，再用隨機收件識別碼確認資料進入 Sheet。
4. 在「全班色彩牆」按「重新整理心得」；看到測試卡片後，再檢查 Google Sheet 的新一列。
5. 將 Sheet 中測試卡片的 M 欄改成「隱藏」，重新整理色彩牆，確認卡片消失。
6. 再用一份測試資料選**只給教師**，確認 Sheet 有收件，但公開牆沒有出現。

## 若出現問題

- **色彩可操作，但顯示「尚未連線」**：網站的 `GAS_WEB_APP_URL` 尚未填好、格式不正確，或你上傳到 GitHub 的仍是舊版 `index.html`。
- **無法讀取 Google Sheet**：檢查 Apps Script 的 `setup()` 是否完成；Web App 存取權是否為「所有人」；是否使用 `/exec`；有些單位的帳號禁止公開部署。
- **點送出後一直無法確認**：查看 Sheet 是否已新增資料。如果已有新增，**不要立刻重送**。在 Safari 或有嚴格隱私設定的瀏覽器，隱藏表單的跨網域請求可能受限制，建議以 Chrome／Edge 測試並保留紙本或 Google 表單備案。
- **已投稿，但看不到卡片**：學生可能選了「只給教師」，或教師把 M 欄設為「隱藏」。若是公開投稿，請按「重新整理心得」。
- **修正 Code.gs 後仍是舊版**：Apps Script 必須透過 **「部署 → 管理部署作業 → 編輯既有部署 → 新版本 → 部署」**。只按儲存不會更新既有 `/exec`。
- **更改 index.html 後還是舊畫面**：確認 GitHub Pages 已完成更新，並重新整理瀏覽器。
- **Apps Script 提示 Illegal spreadsheet id or key**：此程式不要求你手動輸入 Google Sheet 網址；請確認是從**該份試算表的擴充功能**進入 Apps Script，執行 `setup()`。

## 重要技術說明

- 網站公開資料透過 Apps Script `ContentService` 的 **JSONP GET** 讀取；這個 GET 僅限讀取同意公開的資料、檢查服務狀態與隨機收件回執，**不允許用 GET 投稿**。
- 文字回饋用 POST 傳送（非透過 URL 查詢字串），經由隱藏表單向 Apps Script 送出；前端再確認收件。這是配合 GitHub Pages 和 Apps Script 分屬不同網域所採用的輕量方式。
- 網頁在呈現公開心得時使用文字節點而非插入投稿者提供的 HTML，作品連結也只接受 `https://` 網址；但此套件仍不是大型公開活動專用的安全防護系統。
- 不能將「GitHub 網頁成功打開」視為「Google Sheet 已成功串接」；請依上述六步驟測試收件。

需要修改講座文案時，只改 `github-pages/index.html` 中的可見文字即可；**不要隨意更改表單欄位的 `id` 或 `name`**，以免與後端資料欄位失去對應。
